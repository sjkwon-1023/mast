# ADR-0029: 마크다운 원문 편집과 미저장 내용 보존

- 상태: 채택
- 날짜: 2026-09-20

## 배경과 결정

사용자 요청에 따라 마크다운 뷰어에 Edit, Save, Cancel과 Ctrl+S를 추가한다.
별도 편집기 런타임 없이 textarea를 사용하며, 기존 2 MiB 상한을 유지한다.
미리보기의 raw HTML 이스케이프·링크 무력화·외부 이미지 차단도 유지한다.

- UTF-8 원문을 엄격하게 읽고 BOM과 CRLF 원문을 보존한다. 편집 중 파일 폴링을 멈춘다.
- 마운트되지 않은 뷰를 계속 살려두지 않는다. 수정된 원문과 편집 시작 기준은 탭 ID별
  sessionStorage에 저장해 탭·워크스페이스 전환과 WebView 자동 리로드 후 복원한다.
- 저장 공간 부족으로 백업하지 못한 입력은 이전 내용으로 되돌리고 오류를 표시한다.
  백업하지 못한 변경을 받아들인 뒤 자동 리로드로 잃는 상태를 만들지 않는다.
- 탭·pane·워크스페이스를 닫거나 앱을 종료할 때 미저장 내용을 버리는지 확인한다.
  앱 종료 후 복원은 제공하지 않는다. Tauri의 onCloseRequested가 승인 후 destroy를
  호출하므로 main 창에 core:window:allow-destroy 권한을 부여한다.
- 새 fs_save_markdown 명령은 데스크톱 IPC 전용이다. Remote HTTP/WT에는 노출하지 않는다.
- 백엔드는 원문 일치를 확인하고 같은 디렉터리의 임시 파일을 동기화한 뒤 교체한다.
  앱 안의 저장은 직렬화해 같은 원문의 동시 저장 중 하나만 성공시킨다.
  경로의 심볼릭 링크는 유지하고 링크 대상 파일을 저장한다.
- 외부 편집기가 파일을 바꾸면 저장을 거부하고 사용자의 편집 내용은 유지한다.
  교체 직전에도 원문을 다시 확인하지만 외부 프로세스와의 원자적 비교·교체는
  파일시스템이 제공하지 않으므로 최종 비교와 교체 사이의 경합은 남는다.

## 검증

Rust 테스트로 UTF-8·CRLF, 원문 충돌, 크기·확장자 제한, 동시 저장, Unix 링크·권한 보존을 확인한다.
프런트 테스트로 저장·미리보기 갱신, 충돌 후 편집 내용 유지, 마운트 전환 중 저장,
Ctrl+S, 백업 실패 시 입력 거부, 취소 확인을 검증한다.
Windows 네이티브 저장 테스트를 PR CI에 포함한다. 실제 WSL 9P 경로의 저장과
WebView2 자동 리로드·종료 확인은 WINDOWS-BUILD의 수동 검증 항목으로 남긴다.
